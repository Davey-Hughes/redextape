# TM field width control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `width` select in each TM view's rules panel header (`auto`, then 4 to 64; Davey's placement ruling,
spec D1), one program-wide value, recompiles the program at that field width; a
pinned run that overflows keeps its TM, which steps to its halt in `overflow` while the TM's value says it overflowed
at width N and points to a wider width or auto. Width is stored and shared like encoding, and an example resets it
to auto.

**Architecture:** Core gains a pinned run over an already-lowered program. The wasm session gains `compile_at`,
which keeps an overflowed pinned leg and answers its value as a fault. The `compile` export takes the width, and
`fieldWidths()` lists the choices. The worker's `run` request carries the width, and the UI reads, stores and
shares it beside the encoding.

**Tech Stack:** Rust (redextape-core, redextape-wasm), wasm-bindgen, TypeScript, vitest (node and browser projects).

**Spec:** `docs/superpowers/specs/2026-11-16-tm-width-design.md` (its decisions are cited here as D1 to D22).

## Global Constraints

  `1516aa7` before the stack). `tm-return-tag` merged into `main` as `486df8d` (#179) and the branch was rebased onto
  it, and then onto `538b211`; Task 1 is now `263292c`. Task 2 reuses that fix's `tm::is_overflow_guard` and its
  `overflowed_at` wording function. Task 5's test depends on the fix.
- Every cargo, wasm-pack and commit sets the lane's own `CARGO_TARGET_DIR`. Browser suites and wasm builds run under
  the machine's locks named in the lane brief. Browser worker counts use `VITEST_MAX_WORKERS=N`, never `--maxWorkers`.
  vitest's `-- <name>` does not scope files: pass test file paths.
- Long runs go into a log (`>|`); read the summary lines. Never pipe a gate through `tail`.
- Every new test is seen to FAIL before the change it tests (or under the sabotage named for it). Sabotage: copy the
  file to the record dir, edit, run, restore from the copy, `cmp`. A sabotage that does not fire is a finding: report it.
- UI tests use real gestures (`userEvent.selectOptions`, `userEvent.click`), and assert placement with
  `getBoundingClientRect` and styling with `getComputedStyle`. Values are read through the harness helpers the
  neighbouring tests use (`segments`, `resultsText`).
- Comments say why; no history, no measurements, no `file:line` in tracked source. `///` in Rust, `/** */` in TS.
- `auto` stays byte-for-byte today's behaviour: every existing test passes unedited, except call sites whose
  signature a task changes on purpose (named in that task).
- Never `--no-verify`, `--amend`, push or open a PR. Commit messages are one sentence saying what changed.

## Review Focus

1. A kept overflow never decodes its tapes, whether `compile` overflowed (D11) or a raised cap ran the cursor into
   `overflow` (D12), and its fault is worded for a pinned width. Task 2 tests (c) and (e); the auto half of (e) is
   `tm-return-tag`'s `a_raised_tm_cap_driven_into_overflow_reports_no_value`.
2. The map is built at the pinned width for every leg that exists, the kept overflow included. Task 2 test (f).
3. Auto unchanged: its decline wording, its fitted width, its stored and shared payloads (no `width` key). Task 2 (d),
   Task 4 node tests.
4. A width outside `fieldWidths()` never reaches core: the export throws, storage and links read it as auto.
